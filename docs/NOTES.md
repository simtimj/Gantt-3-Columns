## Safe sync (2026-10-29, Julius: "bulletproof, never lose anything")

- Server: `getDaysRange_` returns `th`/`jh`, `getReference_` returns `ch` (`cellHash_` = short MD5). `saveDay(date, tasks, journal, opts{th,jh,ct,cj})` and `saveReferenceItem(item{fwSync,baseHash,contentChanged})` take the script lock; `syncCol_` writes a column only if it changed and the server copy still matches the base hash, else returns the server copy (`tasks` / `journal` / `content`) without writing. ## Workspace text recovery (2026-11-08)

- `Drafts.html` journals day Tasks/Notes and Reference text before the 700 ms autosave delay. One key per app/page/record prevents stale windows from overwriting each other's pending copies. Serialized snapshots and exact acknowledgement revisions prevent late save replies from clearing newer edits; identical pagehide captures reuse the same revision.
- Drafts retain their original merge base. Pending undo during an in-flight or ambiguously acknowledged save retains the possible written text as its recovery/retry base while keeping the original server hash for conflict detection. No additional server API writes bypass the existing save protocol.
- On reopen, a compact notice opens Review. Restore merges the selected copy with loaded server text; conflicts ask before retaining both versions. A day outside the initial range is fetched before recovery, and current pending saves block restoration. A missing Reference card stays previewable/exportable; it is never automatically recreated. Discard removes only the selected unchanged revision.
- Before adopting a historical copy, its replacement must be stored successfully. Failed storage retains prior durable copies, warns the user and keeps current in-memory text exportable. Corrupt entries are preserved for download. Recovery is local to the same browser/profile/origin and configured app URL; eviction, clearing storage, denied storage or private-session loss can remove recovery data. It is not cross-device sync or historical backup.
- Scope: day Tasks/Notes and Reference text. Plan/Scratch editors, Focus and timer queues keep their existing persistence; Reference order/collapse are not a durable text draft. Rollback of client code leaves recovery keys intact; export/recovery needs the draft module or a compatible reader. No automatic server restore occurs at startup.
- Tests: `tools/draft-test.mjs`; `tools/smoke.mjs` includes actual page close/reopen with changed server fixtures on desktop/phone, reviewed merge/save, and deleted-card retention. Google services are mocked; live phone/storage behavior remains To Confirm.

## Workspace save timing (2026-11-08)

- Changed day Tasks/Notes and Reference text/metadata RPCs append anonymous timing samples to a bounded memory buffer (latest 50). Each sample carries a per-page unique sample ID, kind, browser round-trip milliseconds, outcome, and response release/page-build identity; no task text, dates or record IDs are included.
- Samples ride the existing load/sync/import `logSpeed` requests. No logging request is added per save. A report acknowledgement removes only its submitted samples; failed reports retain IDs so analysis can deduplicate an applied report whose acknowledgement was lost.
- Measurements exclude the 700 ms debounce and DOM apply work, include bridge/network/callback latency, and are best effort. Closing the page or overflowing the bounded buffer can lose samples. Offline/error samples have unknown server identity. This buffer is separate from durable edit recovery and is not a complete activity audit. Plan/Scratch/calendar/timer latency needs separate measurement before claiming all-module performance coverage.
